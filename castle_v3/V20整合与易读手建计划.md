# V20：侧墙小修与中文施工总册

## 确定方向

沿用用户认可的V19北立面，只小修截图圈中的东侧外城墙与维修长廊外侧。先核查局部渲染裁切：V19转角图X最大85，漏掉东外城墙X86…87的旧拱框；新图使用完整外包范围，不把裁切当成待拆墙。实际再增加疏密有别的外挑扶垛与长廊上部凸窗，保持音乐、旧构件、路线、内饰和地表。

## 功能单元与验收

1. 独立V20模型：保护编辑器增补侧墙形体，原V19保持；同相机完整转角/近景/整堡配图，逐格差异与支撑/通路检查。
2. 新手施工工作台：原点说明、施工阶段、分区和层次导航；当前区在全堡俯视图中高亮；中文材料、摆法、上下支撑提示；当前/参考/空气分开；逐格查看摆法、每页核对标记可撤销，进度导出导入并绑定版本与原点。不自动操作游戏。
3. 完整V20总册：单一入口、简洁目录（开始/施工/音乐机关/材料/测试）；分开新建顺序与V19改造差异。完整采购表、NBT与当前模型重新生成，旧V18包不覆盖。
4. 保存数据/NBT逐格回读、材料独立计数、教程关键状态与导航/进度契约测试；图片逐张检查。需有针对性的独立复核，重点看施工顺序、摆法与版本混用风险。

## 方案取舍

不继续堆一个长下拉菜单。默认用编号施工阶段和有方块的分区/楼层，构件索引作为查找入口。网格是俯视水平切片；局部定位小地图只表示范围，不伪装成三维施工图。原模型有半砖/门/活塞等特殊安装件，中文方法必须有分支，S3按专用顺序初装，不能机械逐Y照最终闭合态放。

继续离线HTML，不引入React Native/联网服务。UI/UX技能检索脚本缺失，按已读可访问性/信息分层规范实现。既有本地浏览器访问限制保持：PNG视觉核对、静态和DOM替身测试，不绕过限制，也不宣称浏览器/游戏实测。实机更新、走路、灯光、试听仍需独立创造档。

## 实施与复核结果（2026-09-13）

- 完整模型528,573格；在V19之外仅添加1,881格，没有移除或替换旧实体。8根外城墙深扶垛、3组长廊外挑高窗、2盏新落地灯。模型来源和最终图纸统一为V20，旧V18包/V19源文件保留。
- 总册收敛到五个入口：开始与定位、施工工作台、音乐与机关、材料与分工、验收与NBT。6阶段、16×16页、全堡位置小图、中文方法卡；搜索构件只是定位，不代替施工顺序。
- 采用“阶段→A批全高支撑→B批全高元件→每批Y由低到高/同层分区”的次序，共13,957页。特殊机关另有初装流程，不把S3关闭态活塞头当材料或初装步骤。
- 独立复核促成薄件自动连接校准、跨分区墙火把支撑优先、倒挂砂轮安装说明；进度写入失败曾被导入成功文案覆盖，已添加失败复现测试并修复。保存状态同时出现在工作台和材料页，提醒及时导出。
- 83项相关Python测试通过（37.518秒）；纯中文摆法和完整脚本DOM替身另测。四张最终PNG均已查看，模型、材料、页面与324个含空气NBT逐格回读核对。最终文件哈希与ZIP校验以release_v20/verification.json、SHA256SUMS.json为准。
- 未运行浏览器/游戏，没有改动真实存档或服务器。下一步是独立创造档试听、走路、方块更新、机关和夜间验收，不是继续堆新的离线版本。
